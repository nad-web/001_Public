# Present your work credibly

## Use the library as the front door

Link the live catalogue from your GitHub profile and the repository’s About panel. The catalogue shows concepts immediately, but a strong showcase should emphasize ready apps once they exist.

Keep stages accurate. A planned idea is a useful roadmap item, and a prototype is an honest experiment; neither should be presented as a finished release.

## Give each ready app a small case study

Use `docs/case-study.md` inside the app and include:

| Evidence | What it demonstrates |
| --- | --- |
| Specific problem and audience | Product thinking |
| Clear first-version scope | Prioritization |
| Working live demo | Implementation ability |
| Complete source and readable commits | Maintainable development |
| Real screenshot with sample data | Actual result |
| Technical decisions and tradeoffs | Engineering judgment |
| Observed checks and edge cases | Quality discipline |
| AI assistance and human corrections | Responsible AI collaboration |
| Known limits and next improvement | Honest reflection |

Keep the case study short enough to read in a few minutes. A reviewer should be able to understand the problem, try the demo, inspect the source, and assess what you learned.

## Describe skills through evidence

Prefer “Implemented validated expense inputs, tested totals and rounding, and added local export/reset” over a generic claim of financial app expertise. Prefer “Reviewed German examples and tested recall state” over a claim that an unfinished exercise is a complete language course.

Avoid invented users, impact numbers, test coverage, certifications, or performance improvements. Report measurements only when you collected them with a stated method.

## First showcase set

Start with Deutsch Daily, Pocket Budget, and Decision Wheel. Together they can demonstrate learning UX, state and persistence, calculations, interaction, responsive design, accessibility, deployment, and AI collaboration. Expand after those releases are useful and documented.

## Finishing details

- Use clear names and descriptions consistently in the gallery, README, and manifest.
- Verify every live demo and source link after deployment.
- Use original or properly licensed content.
- Capture screenshots without personal records or browser credentials.
- Keep the setup guide reproducible from a clean checkout.
- Record release changes and date your validation evidence.
